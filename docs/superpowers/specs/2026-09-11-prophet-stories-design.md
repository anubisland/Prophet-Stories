# تصميم تطبيق قصص الأنبياء — وثيقة معتمدة

**التاريخ:** 2026-09-11
**الحالة:** معتمدة — جاهزة لكتابة خطة التنفيذ

---

## ١. ما هذا المشروع

تطبيق ويب يعرض **قصص الأنبياء بخط زمني**، بالترتيب الزمني نبياً بعد نبي، معتمداً على
القرآن والسنة الصحيحة وكتب ابن كثير حصراً. لكل نبي مراحل، ولكل مرحلة سرد صوتي، وخريطة
يتتبّع عليها المستمع الأحداث أثناء السرد، وبطاقات للشخصيات المعاصرة، وبطاقات للعبر.

المشروع **مستقل تماماً** عن `../Sera`، لكنه يرث منها المعمارية وقواعدها المكتسبة من
الأعطال. المرجعان: `../Sera` (الخط الزمني للسيرة والخلفاء) و`../islamic_battles`
(أطلس المعارك — محرك السرد والخرائط).

### شاشة المقدمة

أول ما يراه الزائر. تضم: تعريف المشروع، وأهمية قصص الأنبياء
(﴿لَقَدْ كَانَ فِي قَصَصِهِمْ عِبْرَةٌ لِأُولِي الْأَلْبَابِ﴾ — يوسف ١١١)، والمنهج في التوثيق
واستبعاد الإسرائيليات، وكيفية استعمال التطبيق. **ولها سرد صوتي خاص** على نمط
`islamic_battles` (الذي عنده `intro_0` … `intro_4` و`intro_full`).

محتواها في `data/intro.js`، يُحمَّل مع `data/index.js` عند فتح الموقع لأنه أول ما يُعرض.
مقاطعها بلا خريطة ولا شخصيات ولا مصادر — فهي تعريف بالمشروع لا رواية تاريخية.

## ٢. القرارات المعتمدة

| القرار | المعتمد | السبب |
|---|---|---|
| الاستقلالية | مستودع وموقع مستقلان | لا يخاطر بكسر `Sera` الحيّة |
| البيانات | ملف لكل نبي + تحميل عند الطلب | `Sera/data.js` بلغ ٦٦١ ك.ب في ملف واحد |
| مزامنة الخريطة | مقاطع سردية + توقيتات مولّدة آلياً | الأصوات تختلف مددها؛ التوقيت اليدوي ينحرف |
| الأنبياء قليلو المادة | عدد مراحل متغيّر حسب الثابت | القالب الثابت يُغري بملء الفراغ بالإسرائيليات |
| اللغة | عربي أولاً، والبنية ثنائية | الحقول `En` موجودة وفارغة — لا إعادة هيكلة لاحقاً |
| نقطة البدء | نوح ﷺ نموذجاً، ثم آدم | نوح ينطبق على القالب حرفياً؛ آدم استثناء |
| الأصوات | ثلاثة (اثنان يُولَّدان) | خفّض نوحاً من ٥٠ ملفاً إلى ١٥ |
| التلاوة | الحصري افتراضياً + قائمة اختيار | طلب المستخدم |
| الإسرائيليات | مرفوضة بنيوياً، لا مصنّفة | لا باب تدخل منه أصلاً |

## ٣. المعمارية وخريطة الملفات

### قيود حاكمة

- **بدون أدوات بناء، بدون إطار عمل، بدون اعتماد npm وقت التشغيل.** يعمل من `file://`
  ومن أي مستضيف ساكن.
- **لا `fetch` ولا `<script type="module">`** — كلاهما محظور على `file://` بسبب CORS.
  التحميل الديناميكي يكون **بحقن وسم `<script>` كلاسيكي**، وكل ملف بيانات أو توقيتات
  يكون `.js` يُسند لمتغير عام، لا `.json`.
- **كائن حالة واحد**، لا متغيرات عامة متناثرة.

### الملفات

```
index.html            الواجهة + شاشة المقدمة + شاشة النبي + خرائط SVG مضمّنة
style.css             نظام التصميم

app/state.js          كائن الحالة الوحيد { SCREEN, PROPHET, PHASE, LANG, VOICE, RECITER }
app/loader.js         حقن <script> لملف النبي عند الطلب + تتبّع المحمَّل
app/nav.js            التنقل بين الشاشات وضبط حالة العرض كاملة
app/audio.js          اختيار الصوت، تشغيل السرد، تشغيل التلاوة
app/mapsync.js        ربط timeupdate بالمقاطع وتحريك تركيز الخريطة
app/render.js         بناء البطاقات: الشخصيات، العبر، المصادر
app/main.js           التهيئة والربط

data/index.js         فهرس خفيف: مفتاح، اسم، ترتيب زمني، حالة (جاهز/قيد الإعداد)
data/intro.js         محتوى شاشة المقدمة ومقاطعها السردية
data/nuh.js           window.PROPHETS.nuh = {...}

audio/<slot>/<prophet>_<phase>_<lang>.mp3
audio/<slot>/<prophet>_<phase>_<lang>.cues.js
audio/<slot>/intro_<n>_<lang>.mp3          سرد المقدمة
audio/manifest.json   فهرس المقاطع المولّدة + أسماء الفتحات الصوتية

tools/gen_tts.py      منقول من Sera ومعدّل ليُخرج التوقيتات
tools/narration_ar.json   النص المشكّل (وقت البناء فقط — التطبيق لا يحمّله)
tools/check_voc.py
tools/check_release.py
tools/check_sources.py    بوابة المنهج العلمي

docs/SOURCES.md  ARCHITECTURE.md  DATA_SCHEMA.md  BUGS.md
```

الشاشة الرئيسية تحمّل `data/index.js` وحده (بضعة كيلوبايتات)، فتفتح فوراً مهما بلغ عدد
الأنبياء. ملف النبي لا يُحمّل إلا عند اختياره.

### حدود الوحدات

كل وحدة لها غرض واحد وواجهة معلومة:

- `state.js` — يملك الحالة. لا أحد غيره يكتب فيها مباشرة.
- `loader.js` — يأخذ مفتاح نبي ويعيد وعداً بجاهزية بياناته. لا يعرف شيئاً عن الواجهة.
- `audio.js` — يأخذ (نبي، مرحلة، صوت) ويعيد عنصر صوت. لا يعرف شيئاً عن الخريطة.
- `mapsync.js` — يستهلك عنصر الصوت + مصفوفة التوقيتات، ويُخرج تركيزاً للخريطة. لا يعرف
  شيئاً عن البيانات.
- `render.js` — يأخذ كائن مرحلة ويبني DOM. بلا حالة.

## ٤. مخطط البيانات

```js
window.PROPHETS = window.PROPHETS || {};
window.PROPHETS.nuh = {
  key: "nuh",
  order: 2,
  nameAr: "نوح", nameEn: "",
  titleAr: "أول رسول إلى أهل الأرض",
  phases: [
    {
      id: "state",
      kindAr: "حال القوم قبل البعثة",
      titleAr: "…", titleEn: "",
      dateAr: "…",  dateEn: "",

      ayah: "…", ayahRef: "سورة نوح، الآية ٢٣",
      ayahEn: "", ayahRefEn: "Surah Nuh (71), verse 23",

      mtAr: "…", mtEn: "",     // عنوان الخريطة
      mdAr: "…", mdEn: "",     // وصف الخريطة
      amb: "dawn",

      beats: [
        { textAr: "…", textEn: "", focus: { x, y, scale }, pin: "wadd", srcRefs: [0, 1] },
        { textAr: "…", textEn: "", focus: { x, y, scale },              srcRefs: [0] }
      ],

      charsAr: [{ i: "👤", n: "…", r: "…" }],
      charsEn: [],

      lessonsAr: ["…", "…"],
      lessonsEn: [],

      srcs: [
        { ref: "صحيح البخاري (٤٩٢٠)", gradeAr: "صحيح", classAr: "ثابت", url: "" },
        { ref: "تفسير ابن كثير (٨/٢٦٠)", gradeAr: "", classAr: "ثابت",
          url: "https://www.islamweb.net/…" }
      ]
    }
  ]
};
```

### ثلاثة فروق مقصودة عن مخطط `Sera`

**١. لا حقل `descAr` مخزّن.** نص السرد يُشتقّ من `beats` بالضمّ وقت التشغيل. في `Sera`
كان `descAr` مخزّناً ومعه نسخة مشكّلة منفصلة في `narration_ar.json`، فانحرفت النسختان
وشحنت صوتاً خاطئاً أكثر من مرة (العصر الأموي ٤٫٨٪ تشكيل، والعباسي ٠٫٦٪، والعثماني تشكيل
آليّ زائف بكثافة ٩١–٩٦٪). مصدر واحد للحقيقة يُلغي هذا الصنف كله. التشكيل يُفهرَس بمفتاح
`<prophet>_<phase>_<beat>`.

**٢. `srcs` كائنات لا نصوص**، تحمل الدرجة والتصنيف ورابط الشاهد. هذا يجعل المنهج شرطاً
يفرضه الكود لا وعداً في وثيقة.

**٣. `lessonsAr` مصفوفة** — بطاقات عبر مستقلة، لا سطر واحد.

`phases` بلا حد أعلى: موسى قد يأخذ عشراً وإدريس واحدة، والواجهة تتعامل مع العدد ديناميكياً.

## ٥. الصوت والمزامنة

مساران منفصلان، ولكل منهما سلوك مختلف عند الفشل.

### أ. سرد النبي — ملفات مرفوعة

MP3 مولّدة مسبقاً و**مرفوعة في المستودع**. تعمل بلا إنترنت ومن `file://`.

| الفتحة | الصوت | المولّد | الاستعمال |
|---|---|---|---|
| `shakir` | شاكر — `ar-EG-ShakirNeural` | ✅ | **الراوي الأساسي — الافتراضي** |
| `story` | سلمى — `ar-EG-SalmaNeural` | ✅ | صوت قصصي أهدأ |
| `classic` | حامد — `ar-SA-HamedNeural` | ❌ | معرَّف في المخطط، لا تُولَّد ملفاته حتى يُطلب |

الصوتان المولَّدان مصريان كلاهما، فتتسق نبرة التطبيق بدل أن تتأرجح بين لهجتين.

### ب. تلاوة الآية — تُبثّ

من `everyayah.com`، تُستخرج آلياً من `ayahRefEn` بصيغة سورة:آية. **القارئ الافتراضي:
الحصري**، مع قائمة اختيار للمستخدم. لا تُرفع في المستودع، وتحتاج إنترنت — فإن انقطع يعمل
السرد وتصمت التلاوة.

**لا صوت آليّ بديل في أي من المسارين.** `speechSynthesis` و`translate_tts` أُزيلا من
`Sera` لأنهما يبدوان آليين ويتجاهلان الصوت المختار. إن غاب مقطع تظهر ملاحظة «الصوت غير
متاح» ويقف الأمر.

### ج. توليد التوقيتات

نعدّل `gen_tts.py` من `comm.save()` إلى `comm.stream()`، فنلتقط أحداث `WordBoundary`
(تحمل `offset` و`duration` و`text` لكل كلمة) ونسجّل اللحظة التي يعبر فيها السرد حدّ كل
مقطع. الناتج `audio/<slot>/nuh_0_ar.cues.js`:

```js
window.CUES = window.CUES || {};
window.CUES["shakir/nuh_0_ar"] = [0, 8.42, 15.20, 23.87];
```

وقت التشغيل: `timeupdate` يقارن `currentTime` بالتوقيتات فينقل تركيز الخريطة عند كل حد.
التوقيتات تُولَّد لكل صوت على حدة، فاختلاف مدد الأصوات لا يكسر شيئاً.

### د. التشكيل — الفخّ الأغلى

`textAr` في الملف **غير مشكّل**. لو غُذّي إلى edge-tts خمّن كل حركة وأخطأ في أواخر
الكلمات والأعلام. لذا يُولَّد الصوت من **نسخة مشكّلة منفصلة** في `tools/narration_ar.json`
(وقت البناء فقط — التطبيق لا يحمّلها، والنص المعروض يبقى مجرّداً).

يجب أن يطابق الهيكل الحرفي لـ `textAr` (إضافة حركات فقط) وأن يكون **مشكّلاً حقيقةً**.
ثلاثة أنماط فشل شُحنت كلها في `Sera`، و`check_voc.py` يمسك كلاً منها:

- **BARE** — نسخ `textAr` كما هو. شُحن بكثافة ٤٫٨٪ و٠٫٦٪.
- **FAKE** — ختم فتحة آليّ بعد كل حرف بلا سكون ولا شدّة. سجّل ٩١–٩٦٪ ومرّ من البوابة
  القديمة وهو يُقرأ خطأً. **الكثافة وحدها لا تثبت شيئاً.**
- **FUSION** — سقوط فواصل يلحم الكلمات فيلفظها المولّد كلمات غير موجودة.

وكذلك: لا حروف غير عربية في نص السرد (دخلت حروف صينية في `Sera` من ترجمة آلية).

## ٦. المنهج العلمي — وكيف يفرضه الكود

### المصادر

**يُعتمد:** القرآن أولاً وحاكماً على ما سواه؛ ثم السنة الصحيحة (البخاري ومسلم خصوصاً)؛
ثم **تفسير ابن كثير**؛ و**قصص الأنبياء لابن كثير**؛ و**البداية والنهاية**.

**بحذر:** تاريخ الطبري — ينقل بأسانيده بلا تصحيح. يُقبل ما وافق القرآن والسنة ويُردّ ما
خالفهما، ولا يُعتمد وحده.

**يُرفض:** قصص الأنبياء للثعلبي، وعرائس المجالس للكسائي، وكل المجاميع غير السنّية.

**أداتا تصنيف:** إسلام ويب وإسلام سؤال وجواب — يُسجَّل رابط الفتوى في `srcs.url` شاهداً
على أن التصنيف ليس اجتهاداً ذاتياً.

### الإسرائيليات مرفوضة بنيوياً

حُذف تصنيف «إسرائيليات مسكوت عنها» من المخطط نهائياً: لا بطاقة موسومة ولا استثناء.
التصنيف ثنائي: **ثابت يدخل، وما سواه لا وجود له.**

> **صراحة تقنية:** لا يمكن لاختبار آليّ أن يكتشف الإسرائيليات دلالياً. أي قائمة ألفاظ
> ستخطئ في الاتجاهين — تمرّر إسرائيلية بصياغة جديدة، وترفض نصاً يذكر الرواية *ليردّها*.
> فالبوابة ليست الكشف بعد الدخول، بل **منع وجود باب**: لا تُسرد جملة بلا إسناد ثابت،
> والإسرائيلية بتعريفها لا تملك إسناداً ثابتاً.

أربع طبقات في `tools/check_sources.py`، من الأقوى إلى الأضعف:

1. **ربط كل مقطع بمصدر (الطبقة الحاسمة).** كل `beat` يحمل `srcRefs` غير فارغة تشير إلى
   مدخلات صحيحة في `srcs`. مقطع بلا مصدر → فشل. فلا نص مسرود يتيم.
2. **لا يُقبل إلا `classAr: "ثابت"`.** أي قيمة أخرى → فشل فوري. لا استثناءات ولا علم تجاوز.
3. **قائمة سوداء للكتب والرواة.** الثعلبي، الكسائي، عرائس المجالس، **وكعب الأحبار، ووهب
   بن منبه** (راويا الإسرائيليات المعروفان)، والإحالة على التوراة أو سفر التكوين أو العهد
   القديم. ظهور أيٍّ منها → فشل.
4. **قائمة تنبيه للمواضع المشهورة** — توقف للمراجعة البشرية ولا ترفض تلقائياً: داود
   وأوريا، وخاتم سليمان والشيطان على عرشه، وأسماء ركاب السفينة وعددهم، وطول آدم وعمره،
   وتفاصيل هاروت وماروت. قد يكون ذكرها **لردّها** وهو مشروع، والآلة لا تفرّق.

### بوابات أخرى في `check_release.py`

- `ayahRefEn` قابلة للتحليل وتُحلّ فعلاً على `everyayah.com`.
- تطابق عدد `data-ar` مع `data-en` في `index.html`.
- تطابق عدد `<section` مع `</section>` (عطل شُحن مرتين في `Sera` وأخلى الموقع).
- تغطية صوتية كاملة: كل مرحلة × صوت مفعّل × لغة موجودة وغير فارغة.
- وجود ملف توقيتات مقابل لكل MP3، وعدد توقيتاته = عدد `beats`.
- تحديث `?v=` في `index.html` عند تغيّر أي ملف `app/*.js` أو `data/*.js` أو `style.css`.

## ٧. معالجة الأخطاء

| الحالة | السلوك |
|---|---|
| ملف بيانات نبي فشل تحميله | رسالة «تعذّر تحميل القصة» + زر إعادة محاولة. لا شاشة بيضاء. |
| مقطع سرد مفقود | ملاحظة «الصوت غير متاح». لا صوت آليّ بديل. |
| ملف توقيتات مفقود | يعمل الصوت، وتثبت الخريطة على تركيز المرحلة الأول. تدهور رشيق. |
| انقطاع الإنترنت | السرد يعمل (مرفوع)، التلاوة تصمت برسالة. |
| `ayahRef` لا تُحلّ | لا زر تلاوة لهذه المرحلة. تُمسك في البوابة قبل الشحن. |

## ٨. الاختبار والتحقق

لا إطار اختبارات ولا مدقق أسلوب — ولن يُضاف. التحقق ثلاث طبقات:

1. **`node --check`** على كل ملف `app/*.js` و`data/*.js` (لا بناء، فهذا هو «التصريف»).
2. **البوابات:** `check_voc.py` بعد أي تعديل بيانات، و`check_sources.py`، ثم
   `check_release.py` **قبل كل حفظ — خروج ٠ أو لا حفظ.**
3. **تحقق بصري** بفتح `index.html` في متصفح، مع قائمة فحص للجوال.

## ٩. نطاق الإصدار الأول

**المقدمة + نوح ﷺ كاملاً.** أي المحرك بكل أجزائه — تحميل عند الطلب، صوتان، مزامنة خريطة،
بطاقات شخصيات وعبر ومصادر، تلاوة بصوت الحصري — مُثبَتاً على قصة واحدة تامة.

ثم آدم ﷺ (وهو الاستثناء: لا قوم سبقوه ولا مدينة، فيُختبر احتمال المخطط للحالة الشاذة)،
ثم بالترتيب الزمني نبياً بعد نبي. وإضافة نبي بعدها عمل روتيني: ملف بيانات، خريطة، تشكيل،
توليد صوت، فحص.

### خارج النطاق صراحةً

- الترجمة الإنجليزية (الحقول موجودة وفارغة)
- الصوت الثالث `classic` / حامد (معرَّف، لا تُولَّد ملفاته)
- أي نبي غير نوح وآدم
- تطبيق جوال أصلي، أو عمل دون اتصال بـ Service Worker، أو حسابات مستخدمين
